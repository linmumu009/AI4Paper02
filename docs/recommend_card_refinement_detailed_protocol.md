# 推荐卡片精简终稿 A/B 预注册协议

冻结时间：2026-08-18（生成本轮新候选输出之前）。

## 评测对象

只评分完整生产精简链路最终落盘、用户实际会看到的卡片。链路包括整卡提示词、最多三次校验重试、首行处理、结构检查/重排、分段压缩与本地兜底。不得再用已被程序拒绝的中间候选代替最终展示结果。

输入固定为同一批 `current` 标准卡片，所有版本逐字共享同一份输入。原始 MinerU 全文、精简前卡片和完整候选输出只保存在仓库外；仓库只保存哈希、聚合分数和盲评结论。

## 样本状态

- 开发集：3篇已授权公开 arXiv MinerU 全文，用于本轮逐轮选择。
- post-hoc：前一实验已经打开的2篇原留出论文，只能用于反证和失败分析。
- 真正隐藏集：本轮没有。任何开发集冠军都不得据此替换线上默认提示词。

## 两类 A/B

1. 类型1：A为不做任何精简的 `current` 卡片原稿；B为当前线上完整精简链路 `r1_field_limits`。
2. 类型2：从当前线上 `r1_field_limits` 开始，按固定顺序挑战 `r4_safe_budget_template`、`r5_atomic_safe_budget`、`r6_evidence_safe_budget`、`r8_atomic_evidence_budget`、`r9_anchor_first_microcopy`。每轮胜者作为下一轮基线；平局保留基线。

## 评分

每篇、每版本均给出0–100分。八字段分别按事实与可追溯性、字段职责、信息价值、精简度和跨字段不重复评分；模型盲评占80%，确定性检查占20%。同时记录：

- 八字段长度与缺失字段；
- 重点思路和分析总结是否恰好3条；
- 原标题与来源是否逐字保留；
- 是否出现输入不存在的数字；
- 最终硬校验通过率；
- 完整生产链路的模型调用次数和兜底率；
- A/B随机换位后的逐字段与整体成对盲评。

## 类型2晋级门槛

挑战者必须同时满足：

1. 开发集均分至少提高2分；
2. 最终硬校验通过率为100%；
3. 事实性均分下降不超过1分；
4. 单候选评审零幻觉、零不受支持声明、零来源外数字；
5. 成对盲评至少半数论文判挑战者获胜；
6. 成对盲评事实性不劣；
7. 成对盲评零新增不支持内容；
8. 成对盲评零实质信息损失；
9. 任一字段均分下降不超过3分。

开发集冠军冻结后，只能进入新的未见隐藏集。隐藏集须达到100%硬校验并通过同样的事实安全与成对质量门槛，才允许新增管理员提示词配置并设为默认。

## 第二阶段增补：对齐后处理提示词

第一阶段完成后才发现，线上后处理仍使用旧“机构：摘要首行”结构，分段上限也宽于八字段合同，并且一句话记忆的行内正文无法进入分段压缩。这些是链路合同冲突，不是某篇论文的专属内容模式。

在生成第二阶段输出前，新增三个隔离变量的候选；晋级门槛保持不变：

- `r10_r1_aligned_fallback`：整卡提示词仍为线上 `r1`，只把首行、结构、简介、重点思路、分析总结、个人观点和一句话记忆的后处理提示词及预算对齐到八字段合同；
- `r11_r4_aligned_fallback`：使用 `r4` 整卡提示词和同一套对齐后处理；
- `r12_r8_aligned_fallback`：使用 `r8` 整卡提示词和同一套对齐后处理。

该设计先比较 `r1` 与 `r10`，隔离“后处理提示词链”的作用；随后再比较不同整卡提示词，避免把两类变化混在一起。旧2篇论文仍只作 post-hoc，不参与规则修改或正式晋级。

### 配对冻结修正

第二阶段第一次启动时发现，即使生成模型、温度和提示词相同，分别调用整卡模型仍可能得到不同的校验重试轨迹。若让 `r1` 与 `r10` 各自重新生成整卡，中间结果的随机差异会被错误归因给后处理提示词，因此该次混杂运行立即中止且不计入结论。

正式第二阶段改为：每篇论文、每个整卡提示词只调用一次并把成功结果或失败兜底状态冻结在仓库外；`r1/r10`、`r4/r11`、`r8/r12` 分别逐字共享同一份冻结中间文本和 `card_rewritten` 状态，再进入旧、新后处理。程序必须校验每一对的中间文本哈希完全一致，任一不一致则整轮失败，不生成结论。完整中间文本仍不得进入仓库。

## 第三阶段增补：合同流程与证据预算

第二阶段结果生成后才发现两个跨样本流程问题：结构重排分支会直接结束，不再执行字段压缩；新短标题提示词把正文限制在10字，低于正式16字合同，可能删除第二个必要辨识点。第二阶段输出和评分保持不变，新增两轮继续共享已经冻结的 `r4` 整卡中间文本：

- `r13_r4_contract_flow`：提示词和预算与 `r11` 完全相同，只跳过不必要的旧结构模型判断，让标准卡片必定继续进入分段精简，用于隔离流程影响；
- `r14_r4_evidence_budget`：在 `r13` 流程上，把标题正文预算恢复为16字，并把简介、重点思路、分析总结、个人观点和一句话记忆的预算提高到接近各字段硬上限；提示词明确保留对照关系、方法名、条件以及带指标/比较对象/方向的数字证据。

比较顺序固定为 `r11→r13→r14`，原晋级门槛不变。若新版本仍未达到100%最终硬校验，或出现新增事实、实质信息损失与逐字段显著退化，仍不得晋级。

`r14` 结果生成后确认其失败来自输出预算紧贴硬上限：模型虽然收到字段上限，但标签、项目符号或轻微超写会让分段重试三次均失败并触发本地兜底。在查看新的完整候选之前，增加 `r15_r4_robust_evidence`：沿用 `r14` 的16字标题与证据保留原则，但给格式预留余量（简介60/75字、三条思路与结论正文合计185字、观点70字、记忆44字），并明确禁止在分析总结中新增“需/应/建议/优先”等行动建议。`r15` 继续逐字共享同一份冻结 `r4` 中间卡片，分别与 `r14` 和当前稳定的 `r13` 配对比较，晋级门槛不变。

`r15` 的调用分类确认，失败分别发生在分析总结和重点思路；问题是整章重写失败会让整卡回退，而不是其他字段质量不足。在查看下一轮候选前，增加 `r16_r4_selective_contract`：继续使用 `r4` 冻结中间卡片和已验证的合同流程；首行正文使用完整16字预算；分段触发阈值改为与正式合同一致（重点思路/分析总结含3个项目符号共213字、观点75字、记忆48字），未超限字段不调用模型；真正超限的三条字段仍以每条55字的可靠余量压缩，分析总结额外禁止生成行动建议。`r16` 与 `r13`、`r15` 配对比较，全部门槛不变。

`r16` 仍在相同长字段上连续三次失败，表明同时加入更多语义约束降低了格式服从稳定性。在查看下一轮候选前，增加最小改动版 `r17_r4_reliable_selective`：触发阈值、16字标题和冻结输入与 `r16` 相同，但字段压缩提示词逐字复用已经在 `r13` 五篇样本上通过的短预算版本；因此相对 `r13` 只改变“未超限字段不再重写”和“标题不低于合同预算”两项。`r17` 与 `r13`、`r16` 配对比较，门槛不变。
