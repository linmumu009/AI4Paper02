# 沉浸阅读内容提示词 A/B 记录

## 目标

验证沉浸阅读内容质量问题来自生成提示词还是前端信息组织，并在最多 4 轮内选择更好的方案。

## 固定条件

- 样本：`2607.08763`
- 来源：服务器本地论文详情接口
- 生成与评审模型：`deepseek-v4-pro`
- 接口配置：服务器 `llm_config` 第 24 项的 DeepSeek 官方接口与密钥，仅覆盖模型名；脚本不会输出密钥
- 温度：0
- 生成上限：16384 tokens
- 评审上限：12000 tokens
- 满意阈值：88/100
- 评分维度：语义分离 20、具体性 20、证据忠实 20、去重复 15、可读性 15、覆盖完整性 10

## 有效结果

| 轮次 | A | B | 分数 | 胜者 |
| --- | --- | --- | --- | --- |
| 1 | 只声明所需结构的最小提示词 | 当前生产提示词 | 88 / 93 | 当前生产提示词 |
| 2 | 当前生产提示词 | 当前提示词 + 沉浸阅读质量契约 | 94 / 90 | 当前生产提示词 |

第 2 轮已超过满意阈值，因此提前停止，没有为了凑满 4 轮继续消耗模型调用。

评审认为当前生产提示词在机制、数据构建、基线、数值结果、局限和待验证问题上更具体，字段覆盖也更完整。加长契约虽然强化了写作规则，却遗漏了部分语义字段，没有带来净收益。

两次无效运行（一次评分规则不一致，一次输出被 token 上限截断）已排除，不计入结论。

## 决策

1. 保留 `Sever/config/config.py` 中现有 `paper_assets_system_prompt`，不把更长的质量契约替换进生产配置。
2. 主要问题定位为前端将已有专用字段重新扁平合并，导致研究问题、贡献、证据、推断和局限失去标签。
3. 沉浸页改为“大章节 → 语义小组 → 原子内容”三级结构，并明确标示作者主张、直接证据、解释推断和风险边界。
4. 历史数据仅有 `text`/`bullets` 时保留兼容回退；一旦存在专用字段，不再混入旧概述造成重复。

## 复现

脚本：`Sever/scripts/evaluate_paper_assets_prompts.py`

示例（在服务器项目目录执行，配置 ID 和论文地址可按需替换）：

```bash
python Sever/scripts/evaluate_paper_assets_prompts.py \
  --source-url http://127.0.0.1/api/papers/2607.08763 \
  --llm-config-id 24 \
  --model-override deepseek-v4-pro \
  --max-rounds 4 \
  --satisfaction-score 88
```

脚本只输出候选编号、评分、评审意见和可见结果摘要，不写出 API 密钥。
