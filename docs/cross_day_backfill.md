# 跨天自动补缺

## 规则

- 仅适用于已启用的多用户每日 arXiv 任务，不改变管理员设置的时间与 DeepSeek 闲时开关。
- 每个调度周期先处理已到时间、且不在冷却中的当日任务；等待当日源就绪、当日完成或额度用尽时才尝试历史任务。
- 在最近 6 个自然日内排查工作日。补缺依据为已存在的自动任务记录，以及已建立调度历史之后未执行的日期；新开启的任务不会突然抓取一周历史数据。较新日期成功推进水位，也不会掩盖其间未执行的缺口。
- 历史日期按从旧到新选择，使用官方日期批次，不使用提交时间近似替代。官方不存在的日期仍记录为等待，不宣称当天没有论文。
- 每个目标日期每天最多尝试 2 次，失败后至少等待 2 小时；次数按实际启动的北京时间计算并持久化到现有任务历史，重启不清零。
- 已成功且数据完整的日期（包括手动完整补跑）不重复。跨天成功不回退 `last_run_date`，也不消耗当日任务的 8 次预算。
- 与手动/当日任务共用主机执行租约；用户阶段并发为 1。共享输入已存在时不强制清空或重做已完成步骤。
- 所有用户的摘要、精简与结构化卡片都通过覆盖率检查才将该批记为成功。单篇失败仍可展示已发布的其他卡片，但保留输入和补缺资格，不用绿色任务状态掩盖缺口。
- 资源清理逐项核验执行租约，跳过正在运行日期的 PDF/MinerU 缓存；无法判断租约时安全停止删除。其他过期资源仍可清理，不需要永久关闭磁盘压力保护。

## 本地验证

```powershell
python -m unittest Sever.tests.test_pipeline_cross_day_backfill Sever.tests.test_pdf_cleanup_service Sever.tests.test_date_notice_service Sever.tests.test_scheduler_resilience_contract Sever.tests.test_pipeline_completion_contract
python -m unittest discover -s Sever/tests -p "test_*.py"
```

验证包含跨日预算重置、北京时间边界、周末排除、官方历史窗口、手动补跑成功去重、启动失败释放租约、当天优先、闲时设置传递、完整性验收和低空间清理保护。

## 发布与运行验收

使用本轮独立绝对路径清单，按 `change_sync_deploy_workflow.md` 执行 Backend 上传/部署。不得上传运行数据库、密钥、生成目录或无关工作区修改。

发布时确认没有运行中的流水线，避免重启截断任务；如需短暂停止调度以串行完成部署、推送、补跑，须保存原始开关并恢复。验收包括服务器文件校验、服务状态、HTTPS/API 响应、GitHub 分支实际提交，以及补跑日期所有配置用户的严格数据覆盖。启动后台任务或排队成功不能作为完成依据。
